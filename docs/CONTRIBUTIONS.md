# Development Guidelines
## Issues
When creating issues, write down the description of the feature/problem
you're trying to solve. If it relates to some other previous issue, make sure to mention that in the form of a link. 
Issues should contain acceptance criteria, which should be denoted by checkboxes.
Ideally also mention the scope of the change/feature.

## Branches

We work with _**feature branches**_, which should be **created from issues** (mentioned above). You can do this by clicking on the "create 
branch" part on the issue's page.

## Commits

Commit template:
`#issueNumber  yourCommitMessage`
E.g.: `#2 Add hello world functionality`
All commit messages shall be written in _present tense_.

## Merge Requests

When you are finished with your feature, you can send a merge request to merge with the main/parent branch. 
Assign these merge requests to any available developer (who also has the role owner/maintainer).
